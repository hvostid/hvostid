# Passport Service

Владеет цифровым паспортом питомца, сопроводительными документами и
оценкой доверия.

> **Статус.** Сервис сейчас поддерживает базовый CRUD цифровых паспортов
> питомцев. Загрузка документов и фото отслеживается отдельно.

## Зоны ответственности

- Хранение и выдача цифровых паспортов питомцев.
- Приём загрузки документов (прививочные карты, ветеринарные
  сертификаты) и сохранение их в MinIO.
- Расчёт оценки доверия по полноте паспорта и валидации документов.

## Эндпоинты

Спецификация доступна по http://localhost:8083/swagger-ui.html.

- `POST /api/v1/passports` -- создать паспорт питомца. `sellerId`
  берётся из `X-User-Id`, пользователь должен иметь роль `SELLER`.
- `GET /api/v1/passports/my` -- получить пагинированный список паспортов
  текущего пользователя. Поддерживает `page`, `size` и `sort`.
- `GET /api/v1/passports/{petId}` -- получить паспорт с прививками,
  доступно владельцу, `MODERATOR` и `ADMIN`.
- `PUT /api/v1/passports/{petId}` -- частично обновить паспорт,
  доступно только владельцу с ролью `SELLER`.
- `DELETE /api/v1/passports/{petId}` -- удалить паспорт владельца.
  Удаление блокируется, пока паспорт связан с опубликованным объявлением или
  объявлением на модерации. При недоступности listing-service или некорректном
  ответе возвращается 503, паспорт сохраняется.
- `POST /api/v1/passports/{petId}/docs` -- загрузить фото или документ,
  доступно только владельцу с ролью `SELLER`.
- `GET /api/v1/passports/{petId}/docs` -- получить список документов,
  доступно владельцу, `MODERATOR` и `ADMIN`. Остальные
  аутентифицированные пользователи видят только `PHOTO`, если паспорт
  связан с опубликованным объявлением.
- `GET /api/v1/passports/{petId}/docs/{docId}` -- получить одноразовую
  временную media-ссылку на содержимое документа.
- `GET /api/v1/passports/{petId}/cover` -- получить cover-фото для
  публичного каталога, если паспорт связан с опубликованным объявлением.
- `DELETE /api/v1/passports/{petId}/docs/{docId}` -- удалить документ,
  доступно только владельцу с ролью `SELLER`.

Документы принимаются в форматах `jpg`, `jpeg`, `png`, `pdf`.
Максимальный размер файла -- 10 MB.

|--------------------|---------------------|-----------------------------------|
| `SERVER_PORT`      | `8083`              | HTTP-порт                         |
| `DB_HOST`          | `localhost`         | Хост PostgreSQL                   |
| `DB_NAME`          | `hvostid_passport`  | Имя базы                          |

| `MINIO_ACCESS_KEY` | `minioadmin`        | Access key MinIO                  |
| `MINIO_SECRET_KEY` | `minioadmin`        | Secret key MinIO                  |

[`application.yml`](./src/main/resources/application.yml).

## Локальный запуск

```bash
docker compose up -d postgres minio minio-init
./gradlew :passport-service:bootRun
```

## Зависимости

Для интеграционных тестов MinIO собирается из закреплённого upstream-коммита
задачей `:passport-service:prepareMinioTestImage`. Она автоматически входит в
`./gradlew check` и `./gradlew build`; Docker должен быть запущен.
Версия исходников и использование кэша описаны в
[`docker/minio-test`](../docker/minio-test/README.md).

- **Обязательно:** PostgreSQL (база `hvostid_passport`), MinIO, Redis.
- **Исходящие зависимости:** Listing Service проверяется перед выдачей
  публичных фото/trust score и перед удалением паспорта.
- **Обратные зависимости:** Listing Service и Matching Service оба
  читают данные паспорта через HTTP.

## Целостность, оценка и жизненный цикл файлов

Создание/обновление принимает `vaccinations: [{name,date,nextDate}]`: отсутствие поля
сохраняет записи, `[]` очищает. До 100 записей, название до 255 символов, дата не раньше
рождения и не в будущем; nextDate не раньше date. Клиент не может назначить верификацию.
Пагинированный `/my` возвращает `firstPhotoDocumentId`; обложки получаются пакетно,
прививки загружаются batch-fetch без отдельного SQL-запроса на каждый паспорт.

Оценка отражает полноту сведений и документов, а не медицинскую гарантию или рейтинг
продавца. Веса: профиль 25, фото 20, сертификат 20, ветзапись 15, даты прививок 15,
модерация 5. `maximum=100`, `availableComponents` перечисляет эти шесть источников.
Совместимые поля sellerRating/sellerSales равны нулю и исключены из шкалы. Одобрение
объявления отмечает паспорт как модерированный; редактирование сбрасывает отметку.

При MODERATION/PUBLISHED запрещены изменения паспорта, его файлов и удаление. Сначала
архивируйте объявление; освобождение ссылки обычно занимает до 10 секунд. Внутренние
PUT/DELETE `/internal/passports/{id}/references/{listingId}` идемпотентны и блокируют ту же
строку, что удаление. Эти маршруты должны оставаться в частной сети сервисов.
Публичные фото и оценка полноты данных доступны только при PUBLISHED-объявлении настоящего
владельца паспорта; старые ссылки, созданные другим продавцом, доступ не предоставляют.

На паспорт разрешено 20 файлов / 100 MB, на файл — 10 MB. PHOTO принимает декодируемые
JPEG/PNG до 25 мегапикселей; расширение, MIME и байты должны соответствовать. PDF разбирается
PDFBox: 1–100 страниц, без шифрования, действий и вложений. Проверяется формат, а не
истинность документов; оригинал PDF сохраняется.

Удаление объектов записывается в `object_cleanup_jobs` вместе с удалением метаданных.
При сбое S3 обработчик повторяет операцию через минуту. Перед загрузкой создаётся устойчивая
задача очистки потерянного объекта; успешная фиксация метаданных отменяет её атомарно.
Обработчик блокирует паспорт перед задачей и не удаляет объект незавершённой загрузки.
Отложенная очистка загрузок начинается через час, объекты со ссылками не удаляются.
Поля attempts/available_at позволяют видеть отказы и очередь; повтор идемпотентен.
