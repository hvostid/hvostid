# Listing Service

Владеет объявлениями о питомцах: создание, обновление, поиск,
фильтрация.

## Зоны ответственности

- CRUD объявлений о питомцах.
- Поиск и фильтрация (город, вид, диапазон цен и т.д.).
- Проверка владельца паспорта и резервирование активных связей через Passport Service.

## Эндпоинты

| Метод  | Путь                         | Auth         | Заметки                             |
|--------|------------------------------|--------------|-------------------------------------|
| GET    | `/api/v1/listings`           | public       | Поиск + фильтры через query-параметры |
| GET    | `/api/v1/listings/{id}`      | optional     | Публично только PUBLISHED           |
| POST   | `/api/v1/listings`           | seller       |                                     |
| GET    | `/api/v1/listings/draft`     | seller       | Восстановить свою форму; 204, если её нет |
| PUT    | `/api/v1/listings/draft`     | seller       | Сохранить свою форму без паспорта |
| PUT    | `/api/v1/listings/{id}`      | seller       | Только владелец                     |
| DELETE | `/api/v1/listings/{id}`      | seller/admin      | Только владелец                     |


Полная спецификация: http://localhost:8082/swagger-ui.html.

Формы используют `GET`, `PUT`, `DELETE /api/v1/listings/drafts/{formId}`: UUID формы принадлежит
отдельной вкладке и доступен только её продавцу. PUT принимает незаполненные поля, `passportId`
и обязательную `version` (0 при создании), возвращает следующую версию. Устаревшая запись даёт
409. После создания объявления клиент удаляет только свою форму. Срок хранения — 90 дней.
Старый единственный `/draft` сохранён для совместимости.

ID паспорта приводится к положительному 64-битному числу без префикса и ведущих нулей,
включая существующие записи. Создание проверяет наличие и владельца паспорта; последующая
замена паспорта запрещена. Правка PUBLISHED возвращает объявление в MODERATION с записью
истории: обновлённые данные публичны только после повторного одобрения. Изменения статуса,
редактирование и порог жалоб сериализуются блокировкой строки объявления.

Перед MODERATION/PUBLISHED создаётся устойчивая задача восстановления, затем резервируется
ссылка на стороне passport-service. Удаление и редактирование паспорта блокируют ту же
строку и запрещены при активной ссылке. Фоновый обработчик блокирует строку объявления и
согласует ссылку с зафиксированным статусом, в том числе после rollback или сбоя процесса.
Освобождение после архивации/удаления асинхронное, обычно до 10 секунд; ошибки повторяются.
Миграция добавляет задачи для старых активных объявлений. Дополнительная проверка
`has-active` внутри блокировки паспорта сохраняет защиту до завершения восстановления ссылок.

Внутренний `GET /internal/listings/passports/{passportId}/has-active` проверяет MODERATION и
PUBLISHED. Публичный `has-published` проверяет PUBLISHED; необязательный `sellerId` дополнительно
проверяет владельца. Passport-service всегда передаёт настоящего владельца паспорта, поэтому
старые ссылки на чужой паспорт не раскрывают его материалы. Объявления с некорректными старыми
идентификаторами можно архивировать/удалять, но нельзя отправлять на модерацию/публиковать.
Внутренние маршруты доступны
только в частной сети сервисов, gateway их не публикует.

## Локальный запуск

```bash
docker compose up -d postgres passport-service
./gradlew :listing-service:bootRun
```

## Зависимости

- **Обязательно:** PostgreSQL (база `hvostid_listing`).
- **Обязателен для создания/модерации:** Passport Service. Недоступность даёт 503; небезопасная запись не выполняется.
- **Обратные зависимости:** Matching Service читает объявления через
  HTTP.

Удаление формы требует `DELETE /api/v1/listings/drafts/{formId}?version=N`; новая сохранённая версия сохраняется с ответом 409.

Ревизии ссылок сохраняются в passport-service: acquire использует `2 * operationId`, согласование — `2 * operationId + 1`. Старый или повторный запрос не восстанавливает освобождённую ссылку после сетевого timeout. При восстановлении нельзя независимо сбрасывать sequence задач и данные паспортов.

При обновлении первый GET отсутствующей формы атомарно переносит старый `/draft` продавца в version1. Другая вкладка не может забрать тот же черновик повторно; существующие формы не перезаписываются.
